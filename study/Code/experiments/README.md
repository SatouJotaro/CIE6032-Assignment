# 优化器对照：从 loss 曲线到可解释证据

```powershell
python Code/experiments/optimizer_study.py --epochs 100 --batch 64 --seeds 7 17 27 --threads 1
```

从课程根目录运行。只需 PyTorch，CPU，无下载。每次在 `Code/runs/` 下创建时间戳目录，保留完整 CSV 与 report.json。

固定同一份带噪双环数据与训练/验证划分；每个 seed 下，各配置的初始参数与 batch 顺序完全相同。比较：SGD 两种学习率、带动量 SGD、Adam 两种学习率。重复种子改变初始化与 batch 顺序，不改变数据划分。

记录的是真实训练结果，包括训练/验证 loss、accuracy、step、梯度范数、训练累计时间、墙钟时间与首次达到预设验证 accuracy=0.90 的步数和时间。阈值未达到时为 null，不以最终耗时代替。测时包含记录开销，CPU 温度/负载与执行顺序也会影响结果，不能作为严格速度基准。

另做一次受控断点续训检查：保存 model+optimizer 后，用同一个下一 batch，核对恢复前后更新是否相同。这不等于已经验证任意随机 DataLoader、Dropout 或 GPU 训练的位级复现。

## 你要真正完成的部分

1. 在运行前预测 SGD 学习率改变、动量、Adam 会如何影响曲线。
2. 亲自复现基线，找到曲线中与你预测不符的地方。
3. 只改变一个因素：batch 大小、样本噪声、网络宽度或初始化。为该变化开新实验。
4. 用相同步数与相同墙钟时间两个视角比较，不把“每 epoch 更快收敛”直接说成“训练更省时”。
5. 保留负结果、配置和证据路径；解释结论局限。
