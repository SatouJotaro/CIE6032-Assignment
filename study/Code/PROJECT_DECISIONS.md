## 工作量上限与验收

框架验证进展（2026-10-05）：[LLaMA-Factory 本机验证](intent_router/FACTORY_VALIDATION.md)已完成。固定 0.9.4 与本机依赖快照，两组完整训练集和 dev 的前缀/loss mask 均核对通过（框架多监督 EOS 后换行）；实际两步 CPU 训练及 adapter 保存成功。系统环境保持原版本。正式 1000/5000 训练及 GPU 成本尚未验证，未付费。

最新进展（2026-10-05）：[SFT 数据准备](intent_router/SFT_PREPARATION.md)完成，固定嵌套的 1000/5000 条训练集与全 dev 格式转换、逐条 token/答案 mask 检查已通过。两步 CPU PEFT LoRA 检查确认冻结权重不变、adapter 更新及保存重载一致。正式 LoRA 训练与 LLaMA-Factory 环境尚未验证，未租卡；两步训练 loss 不是泛化效果。

1. 本地准备：数据检查和固定划分；写评测脚本；TF-IDF + 线性分类器基线；检查模型输入、聊天模板和输出解析。
2. 主实验：同一模型的提示词基线和 LoRA；仅比较 1000 与 5000 条训练数据一个因素，小集为大集子集，按类别抽样并固定种子。记录训练 token 数、步数与耗时；同 epoch 下数据更多也意味着计算更多，不能声称是等算力比较。
3. 完成交付：统一测试评测、错误分析、可重复运行说明、简单输入输出演示。LoRA 不保证获胜，简单基线更好也是有效结论。

验证集用于选提示词、checkpoint 和配置；最终测试集不参与调参。指标包括准确率、Macro-F1、JSON 合法率；无法解析的输出按错误计，不能从语义指标里排除。保存 train/validation loss、耗时、峰值显存、实际费用及失败案例。loss 比较必须采用相同模板、标签掩码与归一化方式。

核心交付只有五项：数据处理、训练配置、评测脚本、实验报告、简单演示。个人工作必须与上游框架提供的功能明确区分。单次实验不支持稳定性或普遍优越性结论；预算允许时复测关键结果。
